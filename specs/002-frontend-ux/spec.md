## Clarifications

### Session 2026-06-09

- Q: 品牌视觉标识（主 accent 色、display 字体、色板）由谁定义？ → A: 沿用 Huashu Design 品位锚点默认值——衬线 display 字体 + 单一暖色 accent（如 rust 橙 `#C04A1A` 或墨绿 `#2D5A27`）+ `oklch()` 中性灰阶，无需额外品牌规范即可开工。
- Q: 可访问性标准（WCAG 等级、键盘导航、屏幕阅读器）应达到什么目标？ → A: 暂不设正式可访问性目标——延至 Plan 阶段作为 nice-to-have 评估，当前不阻塞 spec。
- Q: v1 是否需要支持暗色模式？ → A: 完整支持——从 accent 色派生完整暗色色板，所有组件需通过双主题审计。
- Q: 客户端错误追踪/可观测性应达到什么程度？ → A: 最小化——结构化 `console.error` + `window.onerror` 全局捕获即可，不引入外部监控服务。
- Q: 前端文件操作（下载、文件名渲染）的安全策略？ → A: 基础加固——文件名渲染前剥离 HTML 标签/属性，设置 CSP 头，下载后回收 Blob URL。

## 设计哲学声明 (Design Philosophy Affirmation)

> 本需求说明书中所有交互行为、视觉呈现、布局策略均遵循 Huashu Design 的核心
> 哲学：**从 existing context 出发，不凭空画**；**Placeholder > 烂实现**；
> **系统优先，Don't add filler content**；**一个细节做到 120%，其它做到 80%**；
> **给 variations，不给「最终答案」**。

所有 UI 元素的引入 MUST 通过「该元素是否 earned its place」测试——空白是设计
问题，用构图解决，不是靠编造内容填满。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 双栏布局：硬朗目录树与高呼吸感文件网格 (Priority: P1)

用户打开云盘 Web 应用后，看到左侧固定宽度的目录树面板与右侧自适应宽度的文件网格
区域。目录树以硬朗、结构清晰的层级缩进展示用户的完整目录结构——每个节点仅含必要
信息（名称 + 展开箭头），不附加装饰性图标或彩色 tag。右侧网格中每个文件/目录以
卡片形式展示，卡片之间保有充足的呼吸间距（gap ≥ 16px），视觉上不拥挤。页面整体
色调克制，使用品牌定义的有限色彩，不出现紫色渐变或大面积装饰性色块。

**Why this priority**: 布局是用户与系统交互的第一触点。双栏结构直接影响用户的
空间导航效率。硬朗的目录树设计（无多余装饰）确保信息密度服务于导航目的，而非
视觉噪音。高呼吸感的网格是 Huashu Design「系统优先，不要填充」原则的直接体现——
每个元素必须 earn its place。

**Independent Test**: 在浏览器中打开应用，验证左侧目录树面板固定宽度约 260px，
右侧网格区域填充剩余宽度；点击目录树节点可切换右侧内容；网格卡片间距均匀且在
不同窗口尺寸下保持可读性（最小卡片宽度 180px，自动换行）；页面中不出现紫色渐变、
emoji 图标、圆角卡片 + 左彩色 accent border 等 AI Slop 特征。

**Acceptance Scenarios**:

1. **Given** 用户首次打开应用且已登录，**When** 页面完成加载，**Then** 左侧
   展示用户根目录下的完整目录树（默认展开第一层），每个节点仅包含名称和展开
   箭头——不出现装饰性文件类型图标、不出现彩色 tag、不出现圆角卡片 + 左 border
   accent；右侧展示根目录下的文件/目录网格卡片，背景色为单一中性灰调，不出现
   渐变底色。
2. **Given** 左侧目录树中某个目录有 5 层深度的子目录，**When** 用户逐层展开，
   **Then** 每一层以统一的 20px 缩进呈现，父节点与子节点的视觉层级关系仅通过
   缩进和字重（medium → regular）区分——不依赖彩色指示线或背景色带。
3. **Given** 用户将浏览器窗口从 1920px 缩窄至 1024px，**When** 窗口尺寸变化，
   **Then** 左侧目录树宽度保持不变（260px），右侧网格自动调整列数（卡片最小
   宽度 180px），不出现水平滚动条。
4. **Given** 右侧网格区域有 200 个文件，**When** 用户快速滚动浏览，**Then**
   滚动过程流畅无卡顿，卡片内容始终正确渲染。卡片不包含装饰性 stats 数字、
   无意义的图标堆叠或编造的时间戳。

### User Story 2 - 状态显性化：高保真骨架屏与诚实占位符 (Priority: P1)

任何触发后端 API 请求的操作（加载目录树、获取文件列表、上传计算哈希、搜索文件），
在等待响应期间，对应的 UI 区域 MUST 展示高保真骨架屏（Skeleton Screen）——而非
空白区域、单一转圈图标、或"正在加载…"文字。骨架屏是 Huashu Design 定义的
**诚实占位符**（Honest Placeholder）：其形状与最终加载内容的布局结构精确匹配，
但不编造内容。骨架卡片仅包含矩形色块占位（缩略图区 + 文字行），不出现编造的
文件名、不出现假缩略图、不出现装饰性图标。

**空状态同样遵循诚实原则**：当目录为空时，不编造"示例文件"或"引导数据"来
填充空白——展示简洁的空状态提示即可。

**Why this priority**: 状态显性化是 Huashu Design 的第一原则。API 延迟不可避免，
但空白等待区让用户产生"系统是否卡死"的焦虑。高保真骨架屏建立心理预期。同时，
"诚实占位符"原则确保骨架屏本身不成为 AI Slop 的来源（编造的假内容比空白更
有害——它让用户误以为数据已加载）。

**Independent Test**: 在网络限速至 3G 条件下打开目录，观察右侧文件网格区域是否
先出现与最终卡片布局一致的灰色占位骨架（仅矩形色块，无文字、无图标），数据到达
后骨架平滑过渡为真实内容。进入空目录，验证骨架消失后仅显示空状态提示，不出现
编造的占位文件。

**Acceptance Scenarios**:

1. **Given** 用户点击左侧目录树中一个有 50 个文件的目录，**When** 右侧网格开始
   请求文件列表 API（网络延迟约 2 秒），**Then** 右侧网格立即展示 50 个骨架卡片
   （每个卡片仅包含：正方形缩略图占位矩形 + 两条水平矩形色块模拟文字行），骨架
   带有从左到右的微光扫过动画（shimmer）；API 响应到达后，骨架卡片以交叉淡入
   方式替换为真实文件卡片。骨架卡片中不出现任何文字内容（文件名、大小等均不
   编造）。
2. **Given** 用户在搜索框中输入关键词并回车，**When** 搜索 API 请求发出，
   **Then** 搜索结果区域立即替换为与当前网格布局一致的骨架屏（不编造文件名）；
   搜索完成前，旧内容已被清空，防止用户误读过期数据。
3. **Given** 用户点击上传按钮选择一个大文件（500MB），**When** 文件正在传输且
   后端正在计算哈希，**Then** 文件列表中在目标位置出现一个特殊的"上传中"骨架
   卡片，该卡片显示真实文件名（用户选择的文件）和上传进度条，进度条随实际上传
   进度更新。上传完成后通过指定动效（见 US3）转化为正式文件卡片。
4. **Given** 用户进入一个空目录（无任何文件或子目录），**When** 目录加载完成，
   **Then** 骨架屏消失后仅显示一行提示文字"此目录为空"，不出现插画、不出现
   "拖拽文件到此处"引导文案、不出现装饰性空状态图标——空白就是空白，诚实告诉
   用户。
5. **Given** 某次 API 请求返回错误（如网络超时或服务端 500），**When** 骨架屏
   等待超过 10 秒或收到错误响应，**Then** 骨架屏消失，替换为错误状态提示：
   "加载失败" + "重试"按钮。不编造错误详情代码、不展示装饰性错误图标。

### User Story 3 - 动效反馈：秒传 Hero Reveal 与删除阻尼滑出 (Priority: P2)

关键操作完成后，系统 MUST 通过精确编排的动效向用户传达结果——动效不是装饰，而是
操作结果唯一的视觉确认信号。Huashu Design 的动画哲学要求：**一次 well-orchestrated
的入场动画，而非散落的微交互**。具体规则：

(a) 当文件上传命中秒传（SHA-1 去重命中），上传中骨架卡片 MUST 执行 **Hero Reveal**
动画——卡片从上传进度条的当前位置"绽放"展开为完整文件卡片，伴随缩放 + 透明度
过渡（约 400ms，缓出曲线），让用户明确感知"文件已瞬间就绪"；

(b) 当用户删除文件/目录，对应卡片 MUST 执行**阻尼感滑出**动画——卡片先向右侧
轻微弹性偏移（模拟物理阻力），随后加速滑出并淡出（总约 350ms），相邻卡片自然
补位（约 250ms，合并批量布局更新避免多次重排）。

**Why this priority**: 秒传没有进度条过程，Hero Reveal 是用户感知"操作完成了"
的唯一手段。删除的阻尼滑出模拟物理世界的物体移除直觉，降低误操作的认知负荷。
散落的小动效（hover 放大、点击波纹、加载转圈）必须被禁用——它们分散注意力且
是 AI Slop 的典型特征。

**Independent Test**: 上传一个已存在的文件（秒传），观察上传中卡片是否执行 Hero
Reveal 动画（400ms 内完成）；对任意文件执行删除，观察卡片是否以阻尼滑出离开网格；
验证页面不存在任何 hover 缩放、点击波纹、或独立于操作结果的装饰性动画。

**Acceptance Scenarios**:

1. **Given** 用户上传一个内容已存在的文件（触发秒传），**When** 后端返回秒传
   成功，**Then** 上传中骨架卡片执行 Hero Reveal 动画：卡片以进度条当前位置为
   锚点，先缩小至 80% 再弹性放大至 100% 同时从半透明变为完全不透明（使用 expo
   缓出曲线），动画持续约 400ms——这是页面中唯一的入场动画。
2. **Given** 文件网格中存在文件 `old_report.pdf`，**When** 用户点击删除该文件，
   **Then** 该文件卡片先向右弹性偏移约 8px（150ms，模拟物理阻力），然后加速向
   右滑出视口并淡出至透明（200ms），总时长约 350ms；滑出结束后，后续卡片平滑
   向左补位（约 250ms），不出现跳跃或闪烁。
3. **Given** 用户连续快速删除 5 个文件，**When** 每次删除操作依次触发，**Then**
   每个卡片的阻尼滑出动画独立执行，但后续卡片的补位动画合并为**一次批量布局
   更新**，避免多次 DOM 重排导致的视觉抖动。
4. **Given** 秒传的 Hero Reveal 正在执行中，**When** 用户立即点击该卡片，**Then**
   动画不被打断，完成后正常响应交互（动画期间点击事件排队）。

### User Story 4 - 反 AI Slop 设计约束：无塑料感视觉 (Priority: P1)

整个前端界面的视觉设计 MUST 严格遵循 Huashu Design 的反 AI Slop 准则，确保用户
感知到的是**有作者意图的设计作品**而非"又一个 AI 生成的页面"。本条 User Story
贯穿所有其他 User Story，是质量底线而非独立功能。

**Why this priority**: AI Slop 是「视觉最大公约数」——紫渐变、emoji 图标、
圆角卡片+左 border accent、SVG 手画人脸——它们之所以是 Slop，不是因为丑，而是
因为它们不携带任何品牌信息。用户请设计师是为了**品牌被认出来**，而不是被稀释
成"又一个 AI 做的页面"。反 Slop 不是审美洁癖，是替产品保护品牌识别度。

**Independent Test**: 由设计师/产品负责人逐项检查 Slop 清单中所有项目，确认页面
中不出现任何一项禁用元素；使用浏览器 DevTools 检查 CSS，确认颜色体系使用品牌
定义的有限色板（`oklch()` 或品牌色值），不出现凭空发明的十六进制颜色。

**Acceptance Scenarios**:

1. **Given** 页面整体配色方案，**When** 审核 CSS 颜色定义，**Then** 不出现以下
   特征：激进紫色渐变（`#7C3AED` → `#A855F7` 等）、遍布所有背景的装饰性渐变、
   不知来源的霓虹 glow 效果。色彩从品牌色板或单一 accent 色派生，非品牌色不出
   现在 UI 中。
2. **Given** 文件列表、目录树、按钮等所有 UI 组件，**When** 审核组件样式，
   **Then** 不出现以下 AI Slop 特征：
   - 圆角卡片 + 左侧彩色 border accent（如 `border-left: 3px solid #...`）
   - Emoji 作为功能图标（如 📁 表示文件夹、📄 表示文件）
   - 每个标题/文件名都配装饰性图标
   - 编造的 stats 数字作为装饰（如显示"1,234 files"但此数据无业务来源）
   - 文件类型图标使用 SVG 手画（应为真实缩略图或诚实占位符）
3. **Given** 文件网格中的缩略图展示，**When** 审核图片类文件的缩略图，**Then**
   缩略图来自后端生成的真实缩略图（图片文件）或使用简洁的类型文字标签（非图片
   文件）——不出现 CSS 绘制的假文件图标、不出现 SVG 手画的物品剪影。
4. **Given** 页面整体排版，**When** 审核字体使用，**Then** 展示型文字（标题、
   文件名等）不使用 Inter / Roboto / Arial / system fonts 作为 display font——
   使用有品牌特征的字体配对（如衬线 display + `-apple-system` body）。

### Edge Cases

- **暗色模式切换**: 用户在亮色/暗色模式间切换时，页面 MUST 无闪烁过渡（使用 CSS
  自定义属性切换，过渡时长 200ms），已加载内容不重新请求 API，骨架屏和动画的
  颜色变量同步切换。

- **骨架屏与空数据竞态**: API 在骨架屏展示后 100ms 内返回（极快响应），骨架屏
  最小展示时长 300ms，防止闪烁——但这 300ms 内骨架屏仅展示矩形色块，不显示任何
  编造的文字内容。
- **目录树深层展开**: 用户快速连续点击展开多层目录节点时，每层展开触发的 API
  请求应取消前一个未完成的请求（仅加载最新选中目录），防止骨架屏不断闪烁切换。
- **大目录骨架屏性能**: 目录包含 10,000+ 文件时，骨架卡片 MUST 采用虚拟滚动/
  懒加载，仅渲染可视区域内的骨架。不一次性渲染 10,000 个 DOM 节点——性能崩溃
  本身就是一种糟糕的 UX。
- **秒传未触发 Hero Reveal**: 若秒传响应 <100ms 且 Hero Reveal 动画未能及时
  绑定，降级为直接显示最终卡片（约 150ms 淡入）。不要强行执行一个错位的动画。
- **移动端/窄屏适配**: 屏幕宽度 <768px 时，目录树收起为汉堡菜单，网格占满全宽。
  触屏设备上的删除操作通过长按菜单触发（与桌面端右键菜单一致），动画保持一致。
- **删除操作的撤销**: 删除后 5 秒内底部出现 Snackbar 提示"已删除「文件名」"
  （使用中文直角引号「」而非英文直引号 ""，遵循 Huashu Design 中文排版规范），
  点击"撤销"可将卡片以滑入+弹入动画恢复原位。
- **空目录展示**: 空目录不出现插画、不出现引导文案、不出现占位图标——仅显示一行
  "此目录为空"。空白是诚实的设计决策，不需要填满。

## Requirements *(mandatory)*

### Functional Requirements

#### 布局与结构

- **FR-001**: 界面 MUST 采用双栏布局——左侧固定宽度（默认 260px）目录树面板 +
  右侧自适应宽度文件网格区域，两者之间有清晰但不显眼的分隔（1px 中性灰线或
  留白分隔，不使用彩色渐变分隔条）。
- **FR-002**: 目录树 MUST 以递归缩进结构展示，每层缩进 20px；展开/折叠箭头 MUST
  实时响应用户点击（无网络延迟）；当前选中目录以高亮背景色标识。目录树节点 MUST
  仅包含名称和展开状态指示——不附加文件类型图标、彩色 tag、状态圆点或其他装饰
  元素。
- **FR-003**: 文件网格 MUST 以卡片形式展示每个文件/目录，卡片包含：文件名（单行
  截断+省略号）、文件大小（人类可读格式）、修改时间。卡片最小宽度 180px，自动
  填充列数，卡片间距 ≥ 16px。卡片不包含装饰性边框 accent、不包含文件类型彩色
  标记。

#### 状态显性化（骨架屏与占位符）

- **FR-004**: 所有触发后端 API 请求的 UI 区域 MUST 在等待响应期间展示高保真骨架
  屏。骨架屏的布局结构 MUST 与目标内容的布局结构精确匹配（形状、尺寸、位置一致）。
- **FR-005**: 骨架屏的占位元素 MUST 保持诚实——仅展示灰色矩形色块（`#E0E0E0` 或
  等效中性灰色调），不展示编造的文字、假数据、假图标。骨架卡片中的"文字行"用
  无文字的水平矩形色块表示，不写"Loading..."或编造的文件名。
- **FR-006**: 骨架屏 MUST 包含微光扫过动画（shimmer），最小展示时长 300ms。
- **FR-007**: 当 API 返回空数据时，骨架屏消失后 MUST 仅展示一行文字提示"此目录
  为空"——不出现空状态插画、不出现引导性图文、不出现装饰性图标。空状态就是空
  状态，不编造内容来填充。
- **FR-008**: 当 API 返回错误时，MUST 展示"加载失败" + "重试"按钮。不编造错误
  详情、不展示装饰性错误图标。同时 MUST 通过 `console.error` 输出结构化错误
  日志（格式：`[API_ERROR] {endpoint} {status} {message}`），并通过
  `window.onerror` 全局捕获未处理异常。不引入外部错误监控服务（保持零依赖）。

#### 动效反馈

- **FR-009**: 秒传成功时，上传中骨架卡片 MUST 执行 Hero Reveal 动画——从上传进度
  状态"绽放"为完整文件卡片（缩放 80%→100% + 透明度 0.5→1.0，expo 缓出曲线，
  约 400ms）。这是页面中**唯一**的入场动画——不出现散落的 hover 缩放、点击波纹、
  或加载转圈动画。
- **FR-010**: 文件/目录删除时，对应卡片 MUST 执行阻尼感滑出动画——先向右弹性偏移
  （约 8px，150ms）→ 加速滑出并淡出（200ms），总约 350ms；相邻卡片 MUST 合并
  批量补位（250ms），避免多次 DOM 重排。
- **FR-011**: 文件网格 MUST 支持虚拟滚动：当目录下文件数超过视口可见数的 2 倍时，
  仅渲染可视区域及上下各一屏的 DOM 节点。骨架屏同样遵循此规则。
- **FR-012**: 删除操作完成后 MUST 展示 Snackbar 提示"已删除「文件名」"（使用中文
  直角引号「」），持续 5 秒并提供"撤销"操作。撤销时卡片以滑入+弹入动画恢复。
- **FR-013**: 动画执行期间，用户对同一目标的操作 MUST 排队处理；连续操作 MUST
  合并批量布局更新。

#### 反 AI Slop 约束

- **FR-014**: 页面 MUST 禁止以下 AI Slop 特征的视觉元素：
  - 紫色渐变或不知来源的装饰性渐变背景
  - Emoji 作为功能图标（📁、📄、🔍 等）
  - 圆角卡片 + 左侧彩色 border accent
  - 编造的 stats 数字或装饰性数据
  - SVG 手画的物品/人脸/场景图（缩略图必须是真实缩略图或诚实占位符）
  - 不知来源的霓虹 glow 效果
- **FR-015**: 色彩体系 MUST 采用 Huashu Design 品位锚点默认色板——单一暖色 accent
  （rust 橙 `#C04A1A` 或墨绿 `#2D5A27` 二选一）贯穿全场 + `oklch()` 中性灰阶
  （`oklch(95% 0 0)` 底色 → `oklch(15% 0 0)` 正文）。MUST 同时派生暗色模式色板——
  accent 色不变，底色反转至 `oklch(10% 0 0)`，正文反转至 `oklch(90% 0 0)`，中间
  灰阶按亮度对称映射。所有颜色通过 `oklch()` 或预定义 accent 色值引用——不凭空
  发明新颜色。不出现多色聚类（除非数据维度 ≥ 3 个分类）。
- **FR-016**: 排版 MUST 使用 Huashu Design 品位锚点默认字体配对——展示型文字（标题、
  文件名、目录树节点名）使用衬线 display 字体（Newsreader / Source Serif 4 /
  EB Garamond，三选一），正文（文件大小、修改时间、提示文案）使用系统字体栈
  （`-apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif`）。不得使用
  Inter / Roboto / Arial 作为 display font。
- **FR-017**: 中文文案 MUST 使用直角引号「」替代英文直引号 ""，遵循中文排版规范。
- **FR-018**: 前端 MUST 禁止引入任何产生 AI 塑料感的廉价 UI 组件库。组件必须从零
  构建或使用 Huashu Design 规范许可的组件源——所有组件的外观必须体现"有作者意图
  的设计"而非"默认组件库主题"。具体禁止特征包括但不限于：
  - 组件库默认的 Material Design 蓝色主题
  - 未经品牌调色覆盖的默认圆角和阴影
  - "一行引入、全局默认样式"的 Drop-in 组件库
- **FR-019**: 每个 UI 元素 MUST 通过"earn its place"测试——元素必须承载明确的信息
  或交互目的。不允许出现仅用于"让页面看起来丰富"的填充性内容（如装饰性分割线、
  无数据来源的统计数字、每行标题都配图标）。

#### 响应式设计

- **FR-020**: 布局 MUST 支持响应式断点：≥1024px 默认双栏；768-1023px 目录树宽度
  缩小至 220px；<768px 目录树收起为抽屉式侧边栏（汉堡菜单触发），网格占满全宽。
- **FR-021**: 界面 MUST 支持亮色/暗色双主题——默认跟随系统 `prefers-color-scheme`
  设置，同时提供手动切换入口（置于顶部栏用户头像旁）。暗色模式下骨架屏色块 MUST
  同步调整为暗色等效灰阶（`oklch(25% 0 0)`），shimmer 动画对比度相应降低。Hero
  Reveal 和阻尼滑出动效在暗色模式下行为一致但透明度起始值调整为暗色适配（暗色
  下 0.30→1.0 替代亮色下 0.50→1.0）。
- **FR-022**: 前端 MUST 对所有用户生成内容（文件名、目录名）在渲染前进行 HTML
  实体转义——剥离 `<`、`>`、`&`、`"`、`'` 字符，防止 XSS 注入。文件下载完成后
  MUST 在 60 秒内回收 Blob URL（`URL.revokeObjectURL()`）。页面 MUST 通过 HTTP
  响应头 `Content-Security-Policy: default-src 'self'; script-src 'self'`
  限制脚本来源。

### Key Entities *(前端展示层)*

- **DirectoryTreeNode**: 目录树节点展示模型。关键属性：`name`、`depth`（层级深度）、
  `isExpanded`、`childCount`、`isSelected`。映射至后端 `FileNode`（`type = 'directory'`）。
  **反 Slop 约束**：节点不携带 `icon`、`color`、`badge` 等装饰属性。
- **FileCard**: 文件网格卡片展示模型。关键属性：`fileName`、`fileType`（扩展名）、
  `fileSize`（人类可读）、`modifiedTime`（相对时间）、`thumbnailUrl`（真实缩略图
  或 `null`）、`isUploading`（上传中状态标记）。映射至后端 `FileNode`（`type = 'file'`）。
  **反 Slop 约束**：不包含 `accentColor`、`icon`、`stats` 等装饰属性。当
  `thumbnailUrl` 为 `null` 时展示纯文字类型标签（如"PDF"），不使用 SVG 假图标。
- **SkeletonState**: 骨架屏状态机。属性：`state`（`loading` / `loaded` / `empty` /
  `error`）、`minDisplayMs`（300ms）、`shimmerActive`。**反 Slop 约束**：骨架不
  包含任何文字内容、图标或假数据——仅包含矩形色块的布局结构描述。
- **AnimationIntent**: 动效意图描述。属性：`type`（`hero_reveal` / `damped_slide_out`
  / `slide_in_restore`）、`duration`（毫秒）、`easing`（expo 缓出 / ease-out 等）。
  **反 Slop 约束**：不包含 `hover_scale`、`click_ripple`、`loading_spin` 等散落微
  交互类型——这些在 Huashu Design 中被视为 Animation Slop。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户从点击目录节点到看到骨架屏的间隔 ≤ 100 毫秒（骨架屏即时渲染，
  不等 API 响应）。
- **SC-002**: 骨架屏的布局结构（卡片矩形色块的数量、位置、尺寸）与真实内容加载
  后的布局偏差 ≤ 5%（像素级对齐），用户无法感知"跳动"；骨架屏中不出现任何文字
  内容或编造数据。
- **SC-003**: Hero Reveal 动画帧率稳定在 60fps，动画全程无掉帧。
- **SC-004**: 在包含 5,000 个文件的目录中，滚动帧率 ≥ 55fps，卡片内容无白屏或
  错位。
- **SC-005**: 单次删除操作卡片在 350ms 内完成滑出；连续删除 5 个文件总视觉完成
  时间 ≤ 1.5 秒（含合并补位动画）。
- **SC-006**: 90% 的用户在 5 秒内发现并理解 Snackbar 撤销提示（可用性测试）。
- **SC-007**: 响应式布局在 1920px、1366px、1024px、768px、375px 五个断点上均无
  水平滚动条，最小触控区域 44×44px。
- **SC-008**: **AI Slop 零容忍**：由设计师/产品负责人逐项审核 Huashu Design 反
  Slop 清单（紫渐变、emoji 图标、圆角+border accent、编造数据、SVG 假图、Inter
  作 display font、装饰性渐变、霓虹 glow），页面中 0 项命中即为通过。
- **SC-009**: 色彩审计通过——页面中使用的所有颜色值均能从品牌色板中溯源，不出现
  一次性的、无法溯源的 `#xxx` 颜色。暗色模式色板 MUST 从同一 accent 色派生，
  审计覆盖亮色+暗色双主题。

## Assumptions

- 后端 API 已由 `specs/001-virtual-filesystem` 定义并实现，前端通过 RESTful 接口调用。
- 目标浏览器为近 2 年内发布的主流版本（Chrome、Firefox、Safari、Edge），支持
  CSS `transform`、`opacity` 硬件加速动画，支持 `oklch()` 颜色函数。
- 文件缩略图仅对图片类型文件（jpg/png/gif/webp/svg）由后端生成真实缩略图——非
  图片文件不生成缩略图，前端展示纯文字类型标签（如"PDF"、"DOCX"）。
- 骨架屏的微光动画使用 CSS `background-gradient` + `animation` 实现，不依赖
  JavaScript 定时器驱动骨架。
- Hero Reveal 的缩放原点为上传进度卡片的几何中心（`center center`）。
- 撤销操作的恢复窗口为 5 秒，超时后前端调用后端软删除确认接口。
- 虚拟滚动阈值为视口可见卡片数的 2 倍（目录 ≤ 40 文件全量渲染，>40 启用虚拟滚动）。
- 颜色体系、字体、间距等视觉 Token 沿用 Huashu Design 品位锚点默认值（见 FR-015、
  FR-016），无需等待独立品牌规范即可开工：rust 橙 `#C04A1A` 或墨绿 `#2D5A27`
  为 accent 色、衬线 display（Newsreader/Source Serif 4/EB Garamond）+ 系统
  body、`oklch()` 中性灰阶。
- 不使用任何 Drop-in UI 组件库（如默认主题 Material UI、默认 Ant Design 等）。
  如需组件复用，必须经过品牌调色覆盖且通过反 Slop 审核。
